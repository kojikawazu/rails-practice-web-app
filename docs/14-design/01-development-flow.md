## 開発フロー方針

### ワークフロー

1. **設計** → レビュー待ち（レビュアーの承認を得るまで実装に進まない）
2. **実装** → レビュー待ち（テストコードも必ず書く。承認を得るまでプッシュしない）
3. **プッシュ・PR作成** — 実装レビュー完了後に実施
4. **PR承認・マージ** — 意思決定者が行う

> 各フェーズの完了時はセルフレビュー（`/self-review`）を実施し、次フェーズに進む前に指摘を修正する（`CLAUDE.md` の品質ゲート参照）。

### 権限（承認ゲート）

| フェーズ | レビュー前にできること | レビュー承認後にできること |
|---|---|---|
| 設計 | ドキュメント作成 | 実装着手 |
| 実装 | コーディング・テスト・ローカルコミット | プッシュ・PR作成 |
| PR | — | マージ（意思決定者のみ） |

### 意思決定者の指示

- 意思決定者からの変更指示には従うこと。
- 設計・実装の方針に疑問がある場合は確認を取るが、最終判断は意思決定者に委ねる。

### 指示ショートカット

`CLAUDE.md` で定義された短い指示は、対応するフルアクションとして扱う。本リポジトリの運用に組み込まれている。

| 指示 | アクション |
|------|-----------|
| PR出して | 変更をコミット → push → PR 作成 |
| PR承認しました | main を pull → マージ済みブランチを削除 → main に切り替え |
| Copilotにレビュー依頼出して | PR コメントで `@copilot` メンション付きレビュー依頼を投稿 |
| Copilotからレビュー来ました | レビューコメントを取得・確認し、必要な対応を実施 |
| 〇〇を参考にしてください | 参考先は read-only（変更しない） |

## Git運用方針

### ブランチ戦略

- **GitHub Flow** を基本とする。
- `main` ブランチへの直接コミットは禁止。開発開始時に必ず作業ブランチを切る。
- ブランチ名は用途プレフィックスを付ける（例: `feature/add-task-image`, `fix/login-error`, `docs/refactor-toc`, `chore/add-makefile`）。

### ワークフロー

1. `main` から作業ブランチを切る
2. 作業ブランチでコミット・プッシュ
3. PR（Pull Request）を作成する — **ここまでは自動化OK**
4. PR承認・マージは **必ず人（意思決定者）が行う**（自動マージ禁止）

### リポジトリ構成

- **モノレポ（ルート管理）**。2 つの Rails アプリと共通インフラ・ドキュメントを 1 リポジトリで管理する。

```
rails-task-web-app/
├── docs/                          # 仕様書・設計書
├── rails-task-fullstack-web-app/  # Project 1: フルスタック（MVC + ERB + Turbo/Stimulus）
├── rails-task-api-web-app/        # Project 2: API モード（JWT）
├── docker-compose.yml             # PostgreSQL + MinIO（ミドルウェアのみ）
├── Makefile                       # 開発用タスクランナー
├── README.md                      # プロジェクト概要（必須）
├── CLAUDE.md                      # AI開発ガイド・ルール正本（必須）
├── .claude/rules/                 # 分割ルール（コーディング/テスト/DB 等）
└── .gitignore                     # Git除外設定（必須）
```

### 必須ファイル

- **README.md** — プロジェクト概要・セットアップ手順
- **CLAUDE.md** — AI開発時のコンテキスト・ルール（詳細は `.claude/rules/`）
- **.gitignore** — 以下を必ず除外する
  - `.env` / `.env.*` — 環境変数・シークレット（各アプリは `.env.example` をテンプレートとして持つ）
  - `/log` / `/tmp` / `/storage` — Rails の生成物・Active Storage ローカルファイル
  - `*.pem` / `*.key` — 秘密鍵・証明書
  - `config/master.key` / クレデンシャル系ファイル

### Pushしてはいけないもの

- シークレット情報（DB 接続パスワード・MinIO 認証情報・`master.key`・トークン等）
- 秘密鍵・証明書ファイル
- ローカル環境固有の設定ファイル（`.env`）
- 大容量バイナリファイル
